## 目标
根据用户输入或最新娱乐热点，生成一篇符合今日头条风格的爆款娱乐八卦文章。

## 选题复用规则（选题前必读）
- 写过的选题**不是禁区**，但重写必须满足以下至少一项：
  1. **事件有重大新进展**（如官方回应、数据更新、涉事方道歉/反转）
  2. **间隔超过 7 天**，且能找到全新的差异化切角
- 如果两项都不满足，**主动建议换题**，列出 2-3 个当前更热的备选。
- 判断时对照 `桌面/今日头条/` 目录下的历史文章，检查同一人物/事件是否已有输出。

## 工作流程（按顺序执行）

### 第零步：头条链接抓取（用户给链接时优先执行）
- 当用户提供今日头条文章链接（`toutiao.com/article/xxx` 或 `m.toutiao.com/article/xxx`）时，**第一时间运行抓取脚本**获取原文内容，不要手动尝试 WebFetch 或 requests。
- 抓取命令：`python scripts/fetch_toutiao.py "<头条链接>"`
- 脚本使用 Playwright + 系统 Edge 浏览器（`channel=msedge`），自动渲染 JS 页面后提取标题和正文。
- 抓取结果保存到 `output/toutiao_article.json`，后续直接读取该文件获取原文。
- **为什么不用 WebFetch**：头条页面需要 JS 渲染，直接 requests 或 WebFetch 只能拿到混淆后的 JS 壳，无法获取正文。
- **为什么用 Edge**：Windows 系统自带，无需额外安装 Chromium（`playwright install` 的 CDN 在国内不可用）。

### 第一步：素材采集
- 如果用户未提供具体事件，调用搜索工具搜索近三天内阅读量高、讨论度大的娱乐八卦新闻。
- 关键词示例：明星出轨、恋情曝光、争议言论、综艺撕逼、离婚内幕。
- 也可让用户粘贴一篇参考文章，我们将基于它进行改写（需保证原创性）。

### 第一步半：信息丰富度 & 多方核实
确定选题后，针对核心事件追加搜索，丰富素材厚度：
- **当事人回应**：搜"XX 工作室 回应""XX 微博 发文""XX 声明"获取官方立场
- **时间线梳理**：搜"XX 事件 时间线""XX 事件 始末"整理关键节点
- **关联人物**：搜"XX 前任""XX 绯闻对象""XX 合作演员"拓展八卦厚度
- **过往事件**：搜"XX 争议""XX 翻车""XX 早年"挖掘历史素材
- **网友反应**：搜"XX 评论区""XX 网友 热议""XX 脱粉"获取公众情绪
- **行业背景**：搜相关合同、资本、综艺赛制等背景信息

### 第一步又半：参考账号对标
- 从 `references/accounts.md` 中的 8 个头条娱乐账号搜索同主题文章：
  - 看他们选了哪个切角
  - 标题用了什么套路
  - 评论区什么话题最热
- 学风格不抄内容，找差异化视角。
- 将所有素材记录在 `<material>` 中，包含关键事实、时间线、当事人回应、网友反应、账号对标。

### 第二步：人设注入
- 从 `references/persona.md` 中选取或组合一种人设（默认"毒舌犀利+幽默"）。
- 若用户有偏好，直接采纳。
- 将选定人设的特性（语言风格、用词习惯、态度）应用到全文。

### 第三步：大纲构思
- 参考 `references/outline-template.md` 生成文章大纲。
- 大纲必须包含：
  - 爆炸式标题
  - 导语（设置悬念）
  - 事件经过（按时间线、冲突递进）
  - 深度扒皮（细节、内幕、过往关联）
  - 一针见血评价（人设态度体现）
  - 互动引导（评论区话题）
- 埋下至少两处伏笔，在后续段落点爆。

### 第四步：正文撰写
- 按大纲展开，字数800-1500字。
- **写作技巧**：动笔前必读 `references/lessons.md`，重点关注：
  - 一篇只打一个核心观点（其余信息是子弹不是主攻）
  - 标题用身体叙事/具体数字，不用抽象概念
  - 按时间线传记式推进，保持叙事沉浸感
  - 给主角找至少两个同期对比样本
  - 用具体动作/画面代替大段解释（小切口破大问题）
  - 结尾必须双路径留白引发站队
  - 信息平衡：正面负面两面都写，比例不超7:3
- 严格遵守 `references/formatting.md` 的排版规范：
  - 每个关键观点、结论、金句用**加粗**处理。
  - 段落短小，多用短句，适合手机阅读。
  - 在需要配图的位置插入标记：`[图片：描述，如"某明星与陌生女子牵手照"]`。
- 标题要求：22-30 字（平台上限 30 字），必须包含人名 + 数字 + 情绪反差。参考 `references/formatting.md` 中的六种爆款公式，写标题前搜对标账号同主题标题学结构。

### 第四步半：Writing QA（正文质量控制，强制执行）
- 初稿完成后、进入原创性检查与配图之前，**必须先跑一轮质量检查**。
- 详细标准见 `references/qa-rubric.md`，此处只列流程骨架：
  1. 逐段检查 10 个维度（标题兑现 / Hook / 信息推进 / 冲突悬念 / 阅读节奏 / 信息密度 / 事实表达风险 / AI 味 / 结构 / 结尾），每项打 0-5 分。
  2. 按优先级分类：`critical_issues`（P0）/ `major_issues`（P1）/ `minor_issues`（P2/P3）。
  3. 只修 P0 / P1 及明显 P2，遵循「删除 → 调顺序 → 压缩 → 补充 → 重写」，**少改、有效改**。
  4. 修改后**再跑一轮 QA，最多 2 轮**；2 轮后仍存在的问题写入 `remaining_issues`，停止自动修改，交人工判断。
  5. 生成 `output/article_qa.md` 报告。
- 红线：禁止为「像人」加入错误、禁止制造虚假悬念、禁止把「推测」写成「事实」、禁止机械套模板、不产生永久写作规则。

### 第五步：原创性检查
- 生成全文后，自动用内置知识比对主要平台的热文，给出重复率自评。
- 如果可能重复，自动进行同义改写和结构重组，直至满足首发要求。
- 若无脚本，则手动提示用户"建议用查重工具验证"。

### 第五步半：原文对比（用户给链接时执行）
- 如果用户提供了头条文章链接作为参考，在独立写稿完成后，对比自己的文章和原文章：
  - **切角差异**：我选了什么角度？原文什么角度？哪个更有爆点？
  - **标题对比**：我的标题用了哪种公式？原文标题有什么可学的？
  - **结构差异**：我的叙事结构 vs 原文结构，哪个更适合手机阅读？
  - **评论区热度**：原文评论区什么话题最热？我的互动钩子能不能复制这种热度？
- **原则**：学风格不抄内容，在安全底线内流量第一。如果原文某个技巧（标题节奏、反转埋点、评论区引导）明显更优，吸收改进但不照搬文案。

### 第六步：自动配图与 .docx 生成
- 将正文内容按 JSON 格式组织（参考 `../output/article_data.json` 结构）：
  - `"type": "body"` — 正文段落，`**text**` 标记加粗
  - `"type": "image"` — 配图节点，包含 `query`（百度搜索关键词）和 `description`（占位说明）
  - `"type": "section_title"` — 小标题
  - `"type": "separator"` — 分隔线
- **配图密度**：平均每 200-300 字插入一张图片，全文 800-1500 字对应 4-7 张图。
- **人名消歧必做**：涉及人名的图片查询，必须附加身份区分词（性别/职业/平台/特征），防止同名混淆。
  - 反例：`白冰 偷税` → 返回女演员照片
  - 正例：`网红白冰 男 探店 偷税 出镜认错` → 返回正确的男网红照片
- 运行 `python generate_article.py` 自动完成：
  1. 百度图片搜索 → 下载 → WebP 自动转 JPEG
  2. 底部水印高斯模糊处理（半径 8px）
  3. 嵌入 .docx，宽度 4.5 英寸居中摆放，无图片说明文字
  4. 按日期归档到 `桌面/今日头条/{年份}/{月份}/{日期}/{标题}.docx`
- 图片搜索失败时插入蓝色占位文字，方便手动替换。
- **配图稳定性检查**（每次运行后必做）：
  - 确认 `Result: X/Y downloaded` 中 X=Y（全部下载成功）
  - 确认无水印误判（edge>0.03 且 bright>120 才触发模糊，其他一律 skip 是正常的）
  - 确认 temp_images 目录无旧文件残留（脚本每次运行时 `dl_dir` 已清理，但根目录旧图会被新图覆盖）
  - 如有 Baidu 全部失败的情况，检查网络或 API 限制，Bing 会自动兜底

### 第七步：输出
- `.docx` 仅包含读者内容：标题（正文顶部）+ 章节正文 + 配图 + 结尾互动提问
- 元信息（人设说明、重复率自评、配图清单）不出现在 .docx 中，仅在对话中简要告知用户
- 归档路径：`桌面/今日头条/{年份}/{月份}/{YYYY-MM-DD-标题}.docx`

### 每步自查（强制执行）
每完成一步，立即自检：
- **素材**：主角身份/性别/时间线准确？同名人物已区分？
- **标题**：22-30 字？含人名+数字+情绪词？对标过账号标题风格？
- **正文**：加粗到位？段落短小？无多余元信息？结尾有互动钩子？
- **QA**：10 个维度已打分？P0/P1 已修？是否已生成 `output/article_qa.md`？
- **分点编号**：小标题必须用"一、二、三"中文数字编号，不允许裸标题！
- **配图关键词**：人名带身份区分（性别/职业）？与上下文事件匹配？
- **配图质量**：每张图与文中人物/事件一致？无水印说明文字？

> **版权与合规提醒**：请确保所有生成内容为原创，不直接抄袭可查证的原文段落，如有参考需进行足够的信息重组和观点输出。

> **未来数据闭环**：写作策略（哪种标题/结构更有效）不靠猜，须等数据复盘 Agent 用真实数据验证。接口与模块边界见 `references/future-strategy.md`。
