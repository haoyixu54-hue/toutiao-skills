# Writing QA 正文质量控制规范（V0.4）

> **定位**：Writing QA 是「写作 Skill」与「数据复盘 Agent」之间的**通用质量控制层**。
> 它只回答一个问题——「这篇文章写得是否合格、有没有硬伤、能不能改得更好」。
> 它**不负责**判断「哪种写法在我的账号上更容易爆」——那需要真实数据，属于未来复盘 Agent 的职责。
> **本规范不产生任何「永久写作规则」。**

---

## 一、五条核心原则（先于一切具体规则）

1. **不要为了「像人」而故意加入错误。**
   禁止：故意语病、故意错别字、故意事实错误、故意降低逻辑性、故意加无意义口语、大量使用"其实 / 不得不说 / 说到底 / 你敢信吗"等模板化表达。
   「人味」不是错误，它来自：信息选择、观点、叙事节奏、具体细节、自然表达、合理情绪、有意义的转折。

2. **不能为了提高完读率制造虚假悬念。**
   禁止：标题故意夸大正文不存在的事实、正文故意拖延核心信息、虚构所谓"反转"、把普通事实包装成不存在的惊天内幕、使用没有证据支持的绝对化结论。

3. **不要把写作规则绝对化。**
   "前 80 字一定要出现冲突"这类说法不能作为绝对规则，应理解为"尽快让读者知道为什么值得继续读"。具体长度按文章类型调整。

4. **事实、观察、推测必须区分。**
   "可能是"不能写成"就是因为"；"值得怀疑"不能写成"已经证明"。

5. **不要机械套模板。**
   Hook → 背景 → 冲突 → 信息 → 反转 → 解释 → 新问题 → 结尾 是参考结构，不是每篇必套。
   QA 判断结构是否**有效**，而不是强制所有文章同构。

---

## 二、QA 流程（最多 2 轮，禁止无限循环）

```
初稿
  ↓ 逐段检查 10 个维度 + 打分 + 问题分类
输出问题清单（critical_issues / major_issues / minor_issues）
  ↓ 按优先级只修 P0 / P1 及明显 P2
修改（少改、有效改）
  ↓ 第二轮 QA
仍有问题 → 停止自动修改 → 写入 remaining_issues
  ↓
生成 output/article_qa.md
```

- **最多自动修改 2 轮**。第二轮之后仍存在的问题：**停止自动修改**，写入 `remaining_issues`，交人工判断。
- QA 是「检查 + 修改」，**不是重写**。

## 三、十个检查维度

### 1. 标题-正文兑现
检查：标题承诺了什么？正文是否真的提供？核心内容是否在合理位置出现？是否标题党？标题提问正文是否没回答？标题强调的冲突正文是否没展开？
- 输出字段：`title_promise` / `title_fulfillment` / `problems`。
- 标题有问题可提修改建议，但**不要为了 CTR 故意夸大**。

### 2. Hook（开头）
检查前几段是否迅速进入主题？有无明确信息缺口？有无反常点 / 冲突 / 疑问 / 值得继续读的信息？是否大量背景铺垫？是否出现典型 AI 开场：
- "在中国悠久的历史长河中……""众所周知……""说起……大家都不陌生……""今天我们就来聊一聊……""相信很多人都很好奇……""在这个信息爆炸的时代……"
- 这些表达没有必要就降低使用。**不机械要求"第一句必须冲突"**，按文章类型判断。

### 3. 信息推进（V0.4 最重要模块）
文章是否不断提供**新信息**？
- 理想链：信息 → 新问题 → 新信息 → 新解释 → 新反差 → 新信息。
- 避免：背景 → 背景 → 背景 → 重复观点 → 总结。
- 重点找：重复表达、空洞过渡、同一观点反复解释、大段背景无推进、段落间无逻辑推进、读者读很久却无新信息。
- 对每个主要段落标 `paragraph_function`：`new_fact / explanation / conflict / example / reversal / opinion / transition / summary`。
- **若连续多段只是 transition / summary / opinion → 判定信息推进不足。**

### 4. 冲突与悬念
是否存在值得追踪的问题？（A 发生了什么？为什么？大家原本以为是什么？实际是什么？反常点在哪？）
- **不要强行制造冲突**。事实本身无冲突时，可用信息差、细节、因果、人物选择、历史背景、意外结果作为阅读动力。

### 5. 阅读节奏
段落是否过长？连续长句是否过多？连续抽象解释是否过多？是否长时间无新信息？有无明显阅读疲劳点？
- 建议自然短段落，但**不机械规定"每段 50 字"**。
- 连续大段说明可考虑：拆段 / 加事实 / 加具体细节 / 调整信息顺序。

### 6. 信息密度
每段是否有实际信息价值？识别：空泛形容词、套话、重复信息、无意义总结、无意义情绪、为凑字数加的内容。
- 例："这件事背后，其实隐藏着非常复杂的原因。"——若下一句没真正解释原因，这句就是低价值表达，删或直接进入原因。

### 7. 事实与表达风险
是否存在明显未经证明的事实？是否把推测写成事实？是否绝对化表达？是否有"史书记载"却无依据的说法？是否为制造冲突加入不存在的细节？娱乐新闻是否把网络传闻写成事实？
- 无法确认时用："有说法认为""公开信息显示""目前无法确认""这一说法仍存在争议"。**不编造来源。**

### 8. AI 味
识别：句式过度整齐；大量"首先其次最后"；大量"然而与此同时值得注意的是"；大量"其实说到底不得不说"；每段像标准作文；情绪过于平均；观点重复；总结过度；结尾模板化；每隔几段强行"反转"；过度网络流行语；为"像人"加口语垃圾。
- 目标：**自然、有信息、有节奏、有观点，但不像模板批量生成**。不是让文章变粗糙。

### 9. 正文结构
不强制固定结构，按文章类型判断。可检查是否存在：开头入口 / 核心问题 / 必要背景 / 信息推进 / 关键细节 / 冲突·反差·解释 / 核心答案 / 合理结尾。
- 某部分缺失时判断：是类型本身不需要，还是确实降低阅读体验。

### 10. 结尾
是否突然结束？是否重复全文？是否出现"对此你怎么看？欢迎留言"？是否标准 AI 总结？是否无必要强行升华？是否完成标题承诺？是否留下自然讨论点？
- 文章已完整时，不强行制造问题。

## 四、评分系统（0-5，工具性，不是绝对好坏）

| 维度 | 0-5 分 | 备注 |
|---|---|---|
| Hook | | |
| 信息推进 | | |
| 标题兑现 | | |
| 信息密度 | | |
| 阅读节奏 | | |
| 叙事 / 结构 | | |
| 自然表达 | | |
| 事实表达安全性 | | |
| 结尾 | | |
| AI 模板感 | | **分数越高越严重**（0 = 无模板感）|

- **不用单一"总分"判断文章好坏**。评分是定位问题的工具。
- 最终输出三类：`critical_issues` / `major_issues` / `minor_issues`。

---

## 五、问题分级与修改优先级

| 级别 | 内容 |
|---|---|
| P0 | 事实风险、标题欺骗、严重逻辑问题 |
| P1 | Hook 弱、信息推进不足、标题兑现不足、大量重复、明显低信息密度 |
| P2 | AI 模板表达、句式问题、段落节奏、结尾表达 |
| P3 | 轻微措辞优化 |

- **不要为了优化 P3 而破坏原文。**

---

## 六、修改原则（少改、有效改）

- 禁止"为了让文章更像人"而大量重写。
- 优先级顺序：**删除 → 调整顺序 → 压缩 → 补充必要信息 → 最后才重写**。
- 一句话没价值就删，不要每次重新生成整篇。
